Subscriptions Vs Licenses
Subscription
A subscription is the plan or service agreement you purchase.
Azure Subscription enables you to create resources within the Azure Portal.
- Defines what services and features are available.
- Examples: Microsoft 365 E3, Business Premium, Dynamics 365 Sales.
- Purchased in quantities.
- Can contain multiple licenses/services.

License
A license is the right assigned to a user or device to use a product or service.
- Grants access to those services and features.
- Examples: An E3 license assigned to Elijah, a Business Premium license assigned to a user account.
- Assigned to users/devices from the purchased quantity.
- Consumes one seat from a subscription.

In one sentence: A subscription is what the organization buys; a license is what gets assigned to a user or device so they can use the subscription's services.

Types of Cloud Models
1. Public Cloud
- Cloud services are owned and managed by a third-party provider.
- Resources are shared among multiple customers over the internet.
- Accessed via secure network connection (typically over the internet)
Examples: Microsoft Azure, AWS, Google Cloud.

2. Private Cloud
- Cloud infrastructure is dedicated to a single organization.
Provides greater control, security, and customization.
- Can be hosted on-premises or by a service provider.

3. Hybrid Cloud
- Combines both public and private cloud environments.
- Allows data and applications to move between the two environments.
- Offers flexibility, scalability, and enhanced security.

Cloud Model Comparison
Public Cloud
- No capital expenditure is required to scale up.
- Applications can be quickly provisioned and deprovisioned.
- Organizations pay only for the resources and services they use.

Private Cloud
- Dedicated cloud environment for a single organization.
- Organizations have complete control over their resources.
- Organizations have complete control over security and compliance.

Hybrid Cloud
- Combines both public and private cloud environments.
Provides the most flexibility.
- Organizations can choose where to run their applications and workloads.
- Organizations maintain control over security, compliance, and legal requirements while benefiting from cloud scalability.

Regions
A region is a collection of datacenters located within a specific geographic area.

Key Points
- A region represents a collection of datacenters.
- Regions provide flexibility and scalability for cloud services.
- Regions help preserve data residency requirements by keeping data within specific geographic boundaries.
- Select regions that are geographically close to your users to reduce latency and improve performance.
- Be aware that not all services are available in every region.
- Some cloud services are global services and are not dependent on a specific region.

Benefits of Regions
- Improved performance through lower network latency.
- Compliance with local data residency and regulatory requirements.
- High availability and scalability for applications and services.
- Better user experience by deploying resources closer to users.

Azure Global Presence
- Microsoft Azure has more than 60 regions worldwide.
- These regions support customers across more than 140 countries.

Tip: When deploying resources, choose a region that balances performance, service availability, compliance requirements, and cost.


Region Pairs
- Each Azure region is paired with another region.
- Azure prefers at least 300 miles of separation between datacenters in a regional pair.
- Some services provide automatic replication to the paired region.
- In an outage, recovery of one region is prioritized out of every pair.
- Azure system updates are rolled out to paired regions sequentially (not at the same time).
- Paired regions are members of the same geography, except Brazil.

Availability Options in Azure
Azure provides several availability and disaster recovery options to help ensure applications remain accessible and resilient.


1. Single VM
VM SLA: 99.9% (with Premium Storage)
Description:
Simplest deployment model.
Suitable for basic workloads and lift-and-shift migrations.
Limited protection against hardware or datacenter failures.
Benefit:
Easy to deploy and manage.


2. Availability Sets
VM SLA: 99.95%
Description:
Protects applications from planned and unplanned hardware failures within a datacenter.
Distributes virtual machines across fault domains and update domains.
Ensures that not all VMs are affected by maintenance or hardware issues at the same time.
Benefit:
Protection against failures within a single datacenter.


3. Availability Zones
VM SLA: 99.99%
Description:
Physically separate datacenters within the same Azure region.
Applications and VMs can be distributed across multiple zones.
Provides protection against entire datacenter failures.
Benefit:
Higher availability and resiliency than Availability Sets.


4. Region Pairs (Multi-Region Disaster Recovery)
Description:
Two geographically paired Azure regions connected for disaster recovery.
Supports regional protection while maintaining data residency requirements.
Enables replication and failover between paired regions.
Benefit:
Protection against regional outages and large-scale disasters.


Availability Hierarchy
Single VM → Basic availability for individual workloads.
Availability Sets → Protection from server and maintenance failures within a datacenter.
Availability Zones → Protection from complete datacenter failures within a region.
Region Pairs → Protection from regional outages and disaster recovery scenarios.


SLA Comparison
Single VM: 99.9%
Availability Set: 99.95%
Availability Zone: 99.99%
Region Pairs: Designed for multi-region disaster recovery and business continuity.​‌


Availability Sets
Availability Sets help keep applications online during planned maintenance and unexpected hardware failures within an Azure datacenter.

Update Domains (UD)
- Update Domains are used for scheduled maintenance activities.
- Performance, security, and system updates are applied sequentially across update domains.
- This ensures that not all virtual machines are restarted or updated at the same time.
- Helps maintain application availability during planned maintenance.

Fault Domains (FD)
- Fault Domains provide physical separation of workloads across different hardware within a datacenter.
- Each fault domain represents a group of servers that share common power and network resources.
- If a hardware failure occurs in one fault domain, virtual machines in other fault domains remain available.
Helps protect applications from unplanned hardware outages.

How Availability Sets Improve Availability
- Distribute virtual machines across multiple Fault Domains (FDs).
- Distribute virtual machines across multiple Update Domains (UDs).
- Protect against both planned maintenance and hardware failures.
- Increase application uptime and resilience within a single Azure datacenter.

Key Benefit
By placing two or more VMs in an Availability Set, Azure ensures that your application remains available even when maintenance occurs or when a server rack experiences a hardware failure.​‌

Resource groups
- Containers for multiple resources that share the same life cycle.
- Aggregates resources into a single manageable unit.
- Every Azure resource must exist in one (and only one) resource group.
- Secure at the resource group (or resource) level using role-based access control (RBAC).

    Storage
(All resources managed together in one resource group.)

OR

Option 2: Multiple Resource Groups
    Web and DB resource group
    Virtual Machine resource group
    Storage resource group
(Resources separated into different resource groups based on management requirements.)

Key Points
- Resource groups are logical containers for Azure resources.
- Resources that share a common lifecycle are often placed in the same resource group.
- A resource can belong to only one resource group at a time.
- RBAC can be applied at the resource group level to control access and permissions.
- Resource groups simplify deployment, management, monitoring, and deletion of related resources.​‌

LPR vs RBAC
LPR (Least Privilege Role / Principle of Least Privilege)
- A security principle that states users should be given only the minimum permissions required to perform their job.
- Reduces security risks and limits unauthorized access.
- Focuses on how much access a user should have.

Example: A Help Desk agent can reset passwords but cannot create Global Administrators.

RBAC (Role-Based Access Control)
- An access control model used to assign permissions based on roles.
- Users are assigned roles, and roles contain permissions.
- Simplifies permission management at scale.

Example: In Azure/Entra ID:
- Global Administrator
- User Administrator
- Helpdesk Administrator
- Billing Administrator

Each role has predefined permissions.

Relationship Between LPR and RBAC
RBAC is the mechanism used to implement Least Privilege.
Example:
- Least Privilege says: "Give the user only the access they need."
- RBAC helps achieve this by assigning the user the appropriate role instead of granting excessive permissions.

Easy Memory Tip
LPR = Security Principle ("Give minimum required access")
RBAC = Access Management Method ("Use roles to grant access")
