M365 Subscription
A Subscription is the agreement or plan purchased by an organization.

Examples:
    Microsoft 365 Business Basic
    Microsoft 365 Business Premium
    Microsoft 365 E3
    Microsoft 365 E5

The subscription defines:
    - What services are available
    - How many licenses are included
    - Billing cycle (monthly or annual)
    - Organization tenant entitlement

Example: Your company purchases a Microsoft 365 E3 subscription with 100 seats.

M365 License
A License is a seat from the subscription assigned to an individual user.
When a license is assigned, the user gets access to the services included in that subscription.

Example:
Subscription:
    Microsoft 365 E3
    Quantity: 100 licenses

License Assignments:
    User1 → M365 E3 License
    User2 → M365 E3 License
    User3 → M365 E3 License
...

Simple Analogy
Think of a subscription as a bus bought by the company.
Think of licenses as the seats inside the bus.
    Subscription = Bus
    License = Seat
    User = Passenger

Without a seat (license), a passenger (user) cannot ride.

Azure: License vs Subscription
Azure is a little different.

Azure Subscription
An Azure Subscription is a billing and resource management boundary.

It is used to:
    Create Azure resources
    Track consumption
    Manage costs
    Apply RBAC permissions
    Set budgets and policies

Examples:
    Production Subscription
    Development Subscription
    Test Subscription

Under an Azure subscription, you can create:
    Virtual Machines
    Storage Accounts
    Azure SQL Databases
    App Services
    Networking Resources

Example:

Azure Subscription: Production
 ├── VM01
 ├── VM02
 ├── Storage Account
 └── SQL Database

Azure License
Azure generally does not work like Microsoft 365 user licensing.
Most Azure services are:
    Usage-based
    Pay-as-you-go
    Consumption-based

However, some Azure services require licenses or user entitlements, such as:
    Microsoft Entra ID P1/P2
    Azure Virtual Desktop user licensing
    Microsoft Defender plans
    Azure DevOps user licenses

In Azure, when people say "Azure License," they are often referring to:
    Service plans
    Feature entitlements
    User-based add-on licenses

rather than the core Azure resources themselves.

- M365 Subscription = The package your organization buys.

- Azure Subscription = The billing and resource-management boundary where Azure resources live.
- Azure License = Usually a user/service entitlement that unlocks specific Azure features.

 Microsoft Entra ID / Azure: Security Defaults vs Conditional Access Policies

Both Security Defaults and Conditional Access (CA) are Microsoft security features designed to protect identities and enforce MFA, but they target different levels of security maturity.

What is Security Defaults?
Security Defaults is Microsoft's free, preconfigured security baseline for all tenants. It provides essential protections with minimal administration.

When enabled, it automatically:
    Requires users to register for MFA.
    Requires administrators to use MFA.
    Blocks legacy authentication protocols.
    Protects privileged activities.
    Applies Microsoft's recommended security settings automatically.

Best for:
    Small organizations
    Startups
    Environments without Entra ID P1/P2 licenses
    Organizations that need quick security improvements with minimal configuration

What is Conditional Access?
Conditional Access is a policy-based access control system that evaluates sign-in conditions and decides whether to allow access, block access, or require additional controls such as MFA.

Conditional Access can evaluate:
    User identity
    Location
    Device compliance
    Application being accessed
    Sign-in risk
    User risk
    Client application type

Examples:
    Require MFA only when users are outside the corporate network.
    Block access from specific countries.
    Allow access only from compliant devices.
    Require stronger authentication for administrators.
    Block risky sign-ins.

Key Differences
Feature	                        Security Defaults	            Conditional Access
Cost	                        Included with Entra ID Free	    Requires Entra ID P1/P2
Setup	                        One-click enablement	        Requires policy creation
MFA	                            Microsoft-controlled	        Fully customizable
Legacy Authentication Blocking	Automatic	                    Configurable
User Exceptions	                Not zsupported	                Supported
Device-Based Policies	        No	                            Yes
Location-Based Policies	        No	                            Yes
Risk-Based Policies	            No	                            Yes
Granular Control	            Very limited	                Extensive
Best For	                    Small/simple environments	    Enterprise environments

Can You Use Both Together?
No.

Microsoft does not allow Security Defaults and Conditional Access policies to be active at the same time. When moving to Conditional Access, Security Defaults must be disabled.

Which One Should You Choose?
Choose Security Defaults if:
    ✅ You have Entra ID Free
    ✅ You need quick protection
    ✅ You have a small tenant
    ✅ You don't need exceptions or advanced policies

Choose Conditional Access if:
    ✅ You have Entra ID P1/P2
    ✅ You need granular security control
    ✅ You have remote workers
    ✅ You require Zero Trust security
    ✅ You want location, device, and risk-based access controls

Interview-Style Answer:
    Security Defaults provides Microsoft's predefined baseline security controls such as MFA enforcement and legacy authentication blocking with no customization. Conditional Access provides policy-based, granular access control that evaluates conditions like user, location, device, and risk before granting access. Security Defaults is ideal for basic security, while Conditional Access is the preferred enterprise solution for implementing a Zero Trust security model.

You need either the Global Administrator, Security Administrator, or Conditional Access Administrator role to manage Security Defaults. Security Defaults</Microsoft Entra ID> can be disabled from the Entra admin center.

Steps:
1. Sign in to the Microsoft Entra Admin Center.
2. Navigate to:
Identity
└── Overview
    └── Properties

3. Scroll to the bottom and select Manage Security Defaults.
4. Change Enable Security Defaults to No.
5. Save the configuration.

Important: Disable Security Defaults only after you've prepared your Conditional Access policies; otherwise, you could temporarily reduce your tenant's security posture.

2. What licenses are needed for Conditional Access?
Conditional Access requires Microsoft Entra ID Premium licensing. Specifically:

Supported Licenses
    Microsoft Entra ID P1
    Microsoft Entra ID P2

Common Microsoft 365 Plans That Include Conditional Access
License	                                Conditional Access
Microsoft 365 Business Premium	        ✅ Included
Microsoft 365 E3 + Entra ID P1	        ✅ Included
Microsoft 365 E5	                    ✅ Included
Entra ID P1 Standalone	                ✅ Included
Entra ID P2 Standalone	                ✅ Included
Microsoft 365 Business Basic	        ❌ Not Included
Microsoft 365 Business Standard	        ❌ Not Included

Conditional Access is one of the primary reasons organizations upgrade from Business Standard to Business Premium.

3. Can I migrate from Security Defaults to Conditional Access?
Yes. In fact, this is Microsoft's recommended path for organizations that have Entra ID P1/P2 licensing and require more advanced security controls.

Recommended Migration Approach
Step 1: Verify Licensing
Confirm that affected users have:
    Microsoft Entra ID P1 or P2

or a Microsoft 365 plan containing those licenses.

Step 2: Create Emergency (Break-Glass) Accounts
Create at least one or two emergency Global Administrator accounts.

These accounts should:
    Have strong passwords
    Be monitored
    Be excluded from Conditional Access policies

This prevents tenant lockout during deployment.

Step 3: Recreate Security Defaults with Conditional Access
Typical replacement policies:
        Policy 1:
        Require MFA for all users

        Policy 2:
        Require MFA for administrators

        Policy 3:
        Block legacy authentication

        Policy 4:
        Require compliant devices (optional)

        Policy 5:
        Block risky sign-ins (optional, P2)


These policies provide functionality similar to, and often stronger than, Security Defaults.

Step 4: Use Report-Only Mode
Before enforcing policies:
    Enable = Report-only

Review:
    Sign-in logs
    Potential policy impact
    User experience

This helps identify issues before enforcement.

Step 5: Disable Security Defaults
After validation:
    Security Defaults = Disabled

Remember: Security Defaults and Conditional Access cannot operate together.

Step 6: Enable Conditional Access Policies
Change policy state from:
    Report-only

to
    On

Monitor sign-in logs closely after rollout.

Interview Answer:
    Security Defaults is Microsoft's free, baseline identity protection feature that enforces MFA and blocks legacy authentication. To use Conditional Access, an organization must have Microsoft Entra ID P1 or P2 licenses. Migration involves creating equivalent Conditional Access policies, testing them in Report-Only mode, creating break-glass accounts, disabling Security Defaults, and then enabling the Conditional Access policies. Security Defaults and Conditional Access cannot be active simultaneously.

📝 Registration Campaign
Imagine your teacher reminds everyone in class to sign up for a school trip. A Registration Campaign is like that reminder. It helps people sign up for important security features on their accounts.

Example:
What it is: A reminder that asks people to set up security features.

Real-life example: Your school is starting a new online learning app. The principal keeps sending reminders:

    "Everyone, please register your phone number and email so you can recover your account if you forget your password."

That's like a Registration Campaign. It encourages everyone to sign up for security features.

🔐 Per-User MFA (Multi-Factor Authentication)
Think of MFA like having two locks on your bedroom door instead of one. After entering your password, you also need to prove it's really you, maybe by approving a message on your phone.

Example
What it is: Extra proof that you are really you.

Real-life example: You want to enter a theme park.
    You show your ticket. ✅
    The guard also checks the stamp on your hand. ✅

The ticket is like your password, and the stamp is like the second factor. Even if someone steals your ticket, they still can't get in without the stamp.

🔑 SSPR (Self-Service Password Reset)
Have you ever forgotten a password? SSPR lets you reset your own password without asking the IT team for help. It's like having a spare key that only you can use after answering some security questions.

Example:
What it is: Resetting your password yourself.

Real-life example: You have a locker at school and forget the combination. Instead of asking the janitor for help, you can:
    Answer a few security questions.
    Verify your student ID.
    Create a new combination yourself.

That's like SSPR. You recover access without waiting for someone else to help.

In short:
Registration Campaign = Reminds people to sign up for security.
Per-User MFA = Adds an extra lock to keep accounts safe.
SSPR = Lets you reset your password by yourself. 😊

Easy Way to Remember
Registration Campaign = "Don't forget to sign up!"
Per-User MFA = "Show two proofs that it's really you."
SSPR = "Oops, forgot my password. I'll reset it myself." 😊
