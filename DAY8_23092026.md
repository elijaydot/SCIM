Home / Conditional Access / What If
This screen is the Conditional Access "What If" tool in Microsoft Entra ID (Azure AD). Think of it as a policy simulator.

✅ It lets you test: "If this user signs into this application under these conditions, which Conditional Access policies will apply?"

Let's explain each option like you're 12 years old.

1. Identity
This answers:
    "Who is trying to sign in?"
Select identity type

Users
Test a real user account.
Example:
    elijah@company.com

Service Principals
Test an application identity.
Example:
    Azure Automation
    Logic App
    Service Account

Think of it as:
Users = Human beings Service Principals = Applications/Bots

User
Choose the specific user you want to test.

Example:
    Elijah Aremu

The What If tool checks:
    User groups
    User roles
    User licenses
    Existing policies

2. Target Resource
This answers:
    "What is the user trying to access?"

Select target type
Cloud Apps

Most common choice.
Examples:
    Microsoft 365
    Exchange Online
    SharePoint Online
    Teams
    Azure Management

Cloud Apps
Select the application.
Example:
    Microsoft Teams

The tool checks:
    Would Conditional Access affect this app?

3. Sign-In Conditions
This answers:
    "Under what circumstances is the user signing in?"

Device Platform
The operating system.
Examples:

Windows
    Windows laptop

macOS
    MacBook

Android
    Android phone

iOS
    iPhone/iPad

Linux
    Linux machine

Example:
    Elijah logs into Teams from an Android phone.

Policies targeting Android devices will apply.

Client App  
This means:
    "What type of application is being used to sign in?"

Examples:

Browser
    Chrome Edge Firefox

Mobile apps and desktop clients
    Teams App Outlook App OneDrive App

Exchange ActiveSync
    Older mobile mail apps.

Example:
    Outlook App = Mobile and Desktop Client

Authentication Flow
This describes how the sign-in happens.

Examples:
Browser-based authentication
    User signs in through browser.

Device Code Flow
Common for:
    PowerShell
    CLI tools
    Devices with limited screens

Example:
    Azure CLI sign-in

Uses Device Code Flow.

4. Identity Risk
These settings come from Microsoft Entra ID Protection.

Think:
    "Does Microsoft think this account is suspicious?"

Insider Risk
Checks if user activity may indicate risky internal behavior.

Example:
    Employee downloading huge amounts of company data.
    Unusual internal activity.

Usually used in advanced security scenarios.

Sign-in Risk
This evaluates the current login attempt.

Examples:
Low Risk
    Normal login.

Medium Risk
    Unusual behavior detected.

High Risk
    Highly suspicious login.

Example:
    London yesterday
    Nigeria 5 minutes later

Microsoft may mark it High Risk.

User Risk
Looks at the entire user account.

Question:
    "Does Microsoft believe this account may be compromised?"

Examples:
    Credentials found on dark web
    Password leaked
    Suspicious activities over time

Risk Levels:
    Low
    Medium
    High

5. IP Address
Specify where the login is coming from.

Example:
    40.77.182.32

Useful when testing:
    Named Locations
    Trusted IPs
    Blocked IPs

Example Policy:
    Block logins from unknown IP addresses

You can test whether it triggers.

6. Country
Choose the country where the sign-in originates.
Examples:
    Rwanda
    United Kingdom
    United States
    Nigeria

Useful for Geo-Based Conditional Access.

Example:
    Block access from Russia
    Require MFA outside UK

The What If tool verifies whether these policies apply.

7. Filter for Devices
This is an advanced feature.

It answers:
    "What properties does the device have?"

Property
    Device attribute to check.

Examples:
    device.deviceOwnership
    device.trustType
    device.isCompliant
    device.operatingSystem

Value
The value for that property.

Examples:
Corporate-Owned Device
    deviceOwnership = Company

Personal Device
    deviceOwnership = Personal

Compliant Device
    isCompliant = True

Real Example
Suppose you have this policy:

    Users: All Users

    Application:
    Microsoft Teams

    Conditions:
    Outside trusted locations

    Grant:
    Require MFA


In the What If tool, enter:
    User:
    Elijah

    Cloud App:
    Microsoft Teams

    Country:
    Nigeria

    IP:
    Public IP

    Platform:
    Android

The result will tell you:
    ✅ Policy "Require MFA for Teams" applies

or
    ❌ Policy does not apply

What If Tool = "If this user signs in like this, which Conditional Access policies will be triggered?" 🚦

For Conditional Access administrators, this is one of the safest ways to troubleshoot why a user is being prompted for MFA, blocked, or granted access.
