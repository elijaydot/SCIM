DEVICE REGISTRATION OVERVIEW
Three device identity states to know
1. Microsoft Entra registered
    Usually personal / BYOD (Bring Your Own Device)
    Work account is connected to the device

Relationship: PERSONAL → WORK

2. Microsoft Entra joined
    Typically a cloud-first corporate device
    Device is joined directly to Entra ID

Relationship: CLOUD-FIRST

3. Microsoft Entra hybrid joined
    Existing corporate domain device
    Joined to on-prem AD + registered with Entra

Relationship: ON-PREM + CLOUD

Tip

Identify the relationship first, then think about management and compliance.

Entra Registered vs Entra Joined vs Hybrid Joined

1. Common ownership
    Entra registered: Personal / BYOD
    Entra joined: Organization
    Hybrid joined: Organization

2. Identity relationship
    Entra registered: Work account connected
    Entra joined: Joined to Entra ID
    Hybrid joined: AD domain + Entra ID

3. Cloud-first?
    Entra registered: Often
    Entra joined: Yes
    Hybrid joined: No, hybrid

4. Simple mental model
    Entra registered: "My PC + work account"
    Entra joined: "Company cloud PC"
    Hybrid joined: "Company domain PC + cloud identity"

Quick Summary
Entra Registered
    Personal device
    User simply connects a work account
    Common for BYOD (Bring Your Own Device)

Entra Joined
    Company-owned device
    Managed directly by Microsoft Entra ID
    Designed for cloud-first organizations

Hybrid Joined
    Company-owned device
    Joined to both on-premises Active Directory and Microsoft Entra ID
    Common in organizations transitioning from on-premises to cloud services


MICROSOFT ENTRA HYBRID JOIN
What “hybrid” really means
1. Existing relationship
    The Windows device is already joined to an on-premises Active Directory (AD) domain.

2. Cloud identity
    The device also establishes an identity relationship with Microsoft Entra ID.

3. Result
    One corporate device can participate in both on-premises and cloud identity scenarios.

Simple Explanation
With Microsoft Entra Hybrid Join, a device has two identity relationships:
    On-premises identity through Active Directory (AD)
    Cloud identity through Microsoft Entra ID

This allows the same corporate device to work seamlessly with both:
    Traditional on-premises resources (file servers, domain policies, legacy applications)
    Modern cloud services (Microsoft 365, Entra ID, Conditional Access, Intune)

Mental Model
    Hybrid Joined = Company Domain PC + Cloud Identity
or
    Active Directory + Microsoft Entra ID = Hybrid Join

Simple Explanation
    When a user signs in, Conditional Access evaluates several factors:

    User → Who is attempting to sign in?
    Device → Which device is being used?
    Authentication → How was the user verified (password, MFA, passkey, etc.)?
    Policy → What security requirements must be met?
    Access Decision → Allow or block access.

Example
    Rachel tries to access Microsoft Teams:

    User: Rachel
    Device: Laptop-01
    Auth: MFA completed
    Policy: Device must be Entra joined and compliant
    Result: Access granted

If Laptop-01 is not compliant, Conditional Access can block access or require additional controls before access is allowed.

IMPORTANT DISTINCTION
Joined does not automatically mean compliant

JOINED
Identity relationship
    Who is this device in the directory?

MANAGED
Management relationship
    Is a management service controlling it?

COMPLIANT
Policy evaluation
    Does it meet configured compliance requirements?

Remember
    Identity ≠ Management ≠ Compliance

Simple Explanation
These are three different concepts that are often confused:

1. Joined = Identity
The device has an identity in Microsoft Entra ID.
    Question: Who is this device?
    Example: Laptop-01 is Microsoft Entra Joined.

2. Managed = Management
A management platform (such as Microsoft Intune) controls the device.
    Question: Is someone managing this device?
    Example: Intune pushes security policies, apps, and settings to Laptop-01.

3. Compliant = Meets Security Rules
The device passes the organization's compliance requirements.

    Question: Does the device meet security standards?
    Examples of compliance requirements:
        BitLocker enabled
        Antivirus running
        Supported OS version
        Firewall enabled
        Device not rooted/jailbroken
        

Real-World Example
A device can be:
    ✅ Joined to Entra ID
    ✅ Managed by Intune
    ❌ Not Compliant because antivirus is disabled

In this case, a Conditional Access policy may block access to Microsoft 365 resources until the device becomes compliant.

Easy Memory Trick
    Joined = Who is the device? (Identity)
    Managed = Who controls the device? (Management)
    Compliant = Is the device following the rules? (Security/Policy)

Joined ≠ Managed ≠ Compliant. They are related, but they are not the same thing.

NB: once a device is Entra Joined, it is been managed by the organization/company.

dsregcmd is a built-in Windows command-line tool used to view and troubleshoot device identity and device registration status in Microsoft Entra ID (formerly Azure AD).

The most important command is:
```text
dsregcmd /status
```

What does it tell you?

It shows:

1. Device Join State
Answers:
    Is the device Entra ID Joined?
    Is the device Hybrid Entra ID Joined?
    Is the device Domain Joined?
    Is the device Workplace Joined?

Example:
```text
AzureAdJoined : YES
DomainJoined  : NO
EnterpriseJoined : NO
```

2. User State
Answers:
    Is the signed-in user authenticated to Entra ID?
    Is Single Sign-On (SSO) working?
    Does the user have a Primary Refresh Token (PRT)?

Example:
```text
AzureAdPrt : YES
```

3. Tenant Information
Shows:
    Tenant Name
    Tenant ID
    Authentication URLs

Example:
```text
TenantName : Contoso Ltd
TenantId   : xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

4. SSO and Token Details
Shows whether the device has:
    PRT (Primary Refresh Token)
    Web Account Manager (WAM) status
    SSO capability

Example:
```text
AzureAdPrt : YES
```

A YES usually means users can access Microsoft 365 resources seamlessly without repeatedly signing in.

Why is dsregcmd /status important?
When troubleshooting:
    Conditional Access failures
    Device compliance issues
    Intune enrollment problems
    Hybrid Join problems
    SSO problems
    "Require compliant device" policy failures

dsregcmd /status is often the first command Microsoft support engineers check.

Real-life Example
Rachel cannot access SharePoint because Conditional Access requires a compliant Entra-joined device.

Run:
```text
dsregcmd /status
```

Output:
```text
AzureAdJoined : NO
```

This immediately tells you the laptop is not Entra ID joined, which may be the reason access is being blocked.

Common dsregcmd Parameters
Display Information
```text
dsregcmd /status
```

Displays device join state, tenant details, user state, SSO state, PRT status, and diagnostics.
```text
dsregcmd /status_old
```

Displays the status information in the older output format.

Join / Leave Operations
```text
dsregcmd /join
```

Schedules and monitors Hybrid Entra ID Join (AutoJoin task).
```text
dsregcmd /leave
```

Removes the device registration (unjoins the device from Entra registration). Commonly used during troubleshooting.

PRT (Primary Refresh Token)
```text
dsregcmd /refreshprt
```

Refreshes the Primary Refresh Token (PRT) used for SSO. Useful when troubleshooting authentication issues.

Recovery
```text
dsregcmd /forcerecovery
```

For Entra-joined devices, initiates device recovery and re-registration flow.

Debugging
```text
dsregcmd /debug
```

Provides additional troubleshooting information and verbose diagnostics.

WAM (Web Account Manager)
```text
dsregcmd /listaccounts
```

Lists WAM accounts configured on the device.
```text
dsregcmd /cleanupaccounts
```

Removes WAM accounts from the device. Often used during sign-in troubleshooting.

Certificates
```text
dsregcmd /refreshp2pcerts
```

Refreshes peer-to-peer certificates.

Device Attribute Update
```text
dsregcmd /UpdateDevice
```

Updates device attributes in Entra ID, for example after a device name change.
