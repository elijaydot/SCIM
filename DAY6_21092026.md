Entra ID and Its Identity Entities/Objects
First, What is Entra ID?
Think of Microsoft Entra ID as the security gatekeeper for a school.
Before anyone can enter the school, the gatekeeper checks:
    Who are you?
    Are you really who you claim to be?
    What are you allowed to access?

In the Microsoft world, Entra ID does the same thing for:
    Microsoft 365
    Azure
    Teams
    SharePoint
    Outlook
    Thousands of other apps

Real-Life Example
Imagine your school uses:
    Google Classroom
    Library system
    Exam portal
    School Wi-Fi

Instead of creating a separate username and password for each one, you use one school account.

Entra ID works similarly:
One identity = Access to many services

What is an Identity?
An identity is simply something that can log in and be recognized.

Real-Life Example
At school:
    Students have IDs
    Teachers have IDs
    Principal has an ID

Everyone has an identity.
In Entra ID:
    User accounts
    Service accounts
    Applications
    Devices
can all have identities.

Entra ID Objects
Think of Entra ID as a giant digital database.
Everything stored inside it is called an object.
Like:
    User
    Group
    Device
    Application
They are all objects.
Think of objects as different types of records stored in Entra ID.

1. User Object
A user object represents a person.

Example
You create:
    elijah@contoso.com

This user can:
    Sign into Microsoft 365
    Access Teams
    Read Email
    Access SharePoint
This account becomes a User Object inside Entra ID.

School Example
Student:
    john@school.com

Teacher:
    mrsmith@school.com
Both are user objects.

Properties of a User
Every user has details about them.
Think of a student record card.
Example:
    Name: Elijah Aremu
    Email: elijah@contoso.com
    Department: IT
    Location: Kigali
    Phone: +250 xxx xxx xxx
These details are called attributes or properties.

2. Group Object
A Group is a collection of users.
Instead of managing users one by one, you manage the group.
Example
Suppose your company has:
    100 HR users
Instead of giving permissions to 100 people individually:

Assign permissions once.
Everyone gets access automatically.

School Example
Class:

    John

    Sarah

No need to message everyone individually.

Examples

Real-Life Example

4. Application Object
An Application Object represents an application registered in Entra ID.

Example
A company creates:
    Expense Tracker App

Before users can log in, the app must be known by Entra ID.
So it is registered.
This creates an Application Object.

School Example
Your school creates:
    Homework Portal

Students log in using school accounts.
The portal must first be registered with the school's identity system.
That's the application object.

5. Service Principal Object
This is one of the most important concepts.
Many people find it difficult, but it's actually simple.

Think of it Like This
Application Object = Car Design Blueprint
Service Principal = Actual Car Driving on the Road

Example
Microsoft builds a Teams App.

The blueprint is:
    Application Object

When Contoso company actually uses Teams:
    Service Principal
gets created inside their tenant.

School Example
Blueprint:
    School Bus Design

Actual bus at your school:
    School Bus #12

Application Object = Design
Service Principal = Actual bus

Why Service Principals Exist
Applications need permissions.
Examples:
    Read emails
    Create users
    Read SharePoint files

The Service Principal receives those permissions.
Think of it as the app's identity.

6. Administrative Unit (AU)
An Administrative Unit helps divide management responsibilities.

Example
Company Locations
    Kigali
    Lagos
    Nairobi
Each IT admin manages only their own city.

School Example
One principal cannot manage every school in a country.

Instead:
    School A Principal manages School A
    School B Principal manages School B

Administrative Units work similarly.

7. Contacts Object
A Contact is someone known by the organization but does not have a login account.
Example
Vendor:
    supplier@gmail.com

Stored in directory.
But cannot sign in.

School Example
Parent information stored in school records.
The parent is known by the school, but doesn't have a student account.
That is similar to a contact object.

8. Managed Identity
A Managed Identity is an identity for Azure resources.
Instead of a person signing in, an Azure service signs in automatically.
Example
A Web App needs access to:
    Azure Storage

Bad way:
    Store password in code

Good way:
    Managed Identity

Azure automatically handles authentication.

School Example
Imagine a library door that automatically recognizes teachers without needing a password every day.

Managed Identity works like that.

Secure and automatic.

Example

Methods to Enable Azure MFA

Azure Multi-Factor Authentication (MFA) can be enabled using three different methods:

1. Conditional Access Policy
A Conditional Access policy can be configured to enforce MFA based on specific conditions.

Examples of conditions (signals) used to make the decision:
    User and location
    Device
    Application being accessed
    Real-time risk level

Based on these signals, Entra ID can:
    ✅ Allow access
    🔐 Require MFA
    ❌ Block access

Modern Example: You sign in to Microsoft 365 from your company laptop in London. Access is allowed without extra checks.

Later, someone tries to sign in using your account from another country on an unknown device. Conditional Access detects the risk and requires MFA or blocks the sign-in.

2. Per-User MFA
The Per-User MFA feature enables MFA directly on individual user accounts.

How it works:
    MFA is turned on for specific users.
    Every sign-in attempt requires MFA.
    There are no intelligent conditions or risk evaluations.

Modern Example: Your IT administrator enables Per-User MFA for Elijah.

Every time Elijah signs into:
    Outlook
    Teams
    SharePoint

he must approve the sign-in through the Microsoft Authenticator app.

Think of it like a school that checks every student's ID card every single time they enter, regardless of where they came from.

3. Security Defaults
Security Defaults is Microsoft's basic, preconfigured security package for organizations.

When enabled, Microsoft automatically:
    Requires MFA registration for users
    Protects administrator accounts
    Blocks legacy authentication
    Applies built-in security settings

No complex configuration is required.

Modern Example: A small startup with 10 employees wants better security but has no dedicated IT team.

Instead of building Conditional Access policies, they simply enable Security Defaults and Microsoft handles the basics for them.

Think of it as buying a smartphone with security settings already turned on by default.

Easy Way to Remember
Security Defaults

"Microsoft decides."
    Quick and automatic
    Best for small organizations

Per-User MFA
"User decides."
    Turn MFA on for specific accounts
    Every login gets MFA
Conditional Access

"Conditions decide."
    Smart and flexible
    Uses location, device, risk, application, and many other signals

Summary
Imagine your school has three ways to check students before entering:

Security Defaults
The school has one standard rule for everyone.
    "Everybody must show an ID card."

Per-User MFA
The principal chooses specific students.
    "John and Mary must show an ID card every time."

Conditional Access
The school is smart.
    "If a student comes from a trusted school bus, let them in. If they come from somewhere unusual, ask for an ID card. If something looks suspicious, don't let them in."

That's why Conditional Access is the modern and recommended method, while Per-User MFA is considered legacy, and Security Defaults is the simplest option for smaller organizations. 🔐

    1234

Custom Smart Lockout
Smart Lockout helps stop attackers from repeatedly guessing passwords.

Lockout Threshold
    10

Meaning: After 10 failed sign-in attempts, the account will be temporarily locked.

Example
Someone tries:

    Password1
    Password2
    Password3
    ...
    Password10

After the 10th failure, Entra ID blocks further attempts.

Lockout Duration
    60 seconds
Meaning: The user must wait 60 seconds before trying again.

Real-Life Example
Imagine entering the wrong PIN on your phone too many times.

The phone says:
    "Try again in 1 minute."
This setting works similarly.

Custom Banned Passwords
Organizations can create their own list of forbidden passwords.

Enforce Custom List
    No

Meaning: The organization is currently not enforcing a custom banned password list.

Custom Banned Password List
    (Empty)

This area is where administrators can add passwords that users are not allowed to use.

Example
A company called Contoso might ban:
    Contoso
    Contoso123
    Welcome123
    Summer2026
    Password123

If a user tries to use one of these passwords, Entra ID rejects it.

Password Protection for Windows Server Active Directory
Enable Password Protection on Windows Server Active Directory
    Yes

Meaning: Password protection is enabled not only for cloud users in Entra ID but also for users in the on-premises Active Directory environment.

Why Is This Useful?
Many organizations use both:
    On-Premises Active Directory
    Microsoft Entra ID

This setting ensures both environments follow the same password security rules.

Real-Life Example
A company has:
    London Office AD
    Kigali Office AD
    Microsoft 365

Users cannot choose weak passwords in either environment.

Mode
    Audit

Available options:
    Audit
    Enforced

The current selection is:
    Audit

Audit Mode
Entra ID only monitors and reports violations.

It does not block users yet.

Example
User tries:
    Password123


Entra ID records:
    "This password would have been blocked."

But the password may still be allowed.

Think of a teacher saying:
    "I'm warning you today, but next week I'll start enforcing the rule."

Enforced Mode
Entra ID actively blocks weak or banned passwords.

Example
User tries:
    Password123
    Welcome123
    CompanyName1


Entra ID immediately rejects them.

Think of:
    Warning = Audit Mode
    Actual Punishment = Enforced Mode

Summary of the Configuration Shown
    Smart Lockout Threshold: 10 failed attempts
    Lockout Duration: 60 seconds
    Custom Banned Password List: Not Enabled
    Password Protection for On-Premises Active Directory: Enabled
    Password Protection Mode: Audit



Imagine your school locker system:
✅ If you enter the wrong code 10 times, your locker locks for 60 seconds.
✅ The school can create a list of forbidden locker codes like:
        1234
        0000
        School123
✅ These rules work both in the main school building and branch campuses.
✅ Right now, the school is only watching and reporting bad codes (Audit Mode).
✅ Later, the school can switch to Enforced Mode, where bad codes are completely blocked.

The goal of Password Protection is simple:
