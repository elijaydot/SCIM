This is a very common source of confusion because Microsoft has changed the naming from Azure AD to Microsoft Entra ID.

Quick Summary
Role Type	                                Scope	                    Manages
Entra ID Roles (formerly Azure AD Roles)	Identity/Tenant	            Users, Groups, MFA, Applications, Directory settings
Azure Roles (RBAC)	                        Azure Resources	            VMs, Storage, Networks, Resource Groups, Subscriptions
Azure AD Roles	                            Old name for Entra ID Roles	Same as Entra ID Roles

Key point:
Azure AD Roles = Entra ID Roles (same thing, new name).
Azure Roles are completely different and control Azure resources.

1. Entra ID Roles (Azure AD Roles)
These roles manage the identity platform.
They allow administrators to manage:
    Users
    Groups
    Password resets
    MFA
    Enterprise Applications
    App Registrations
    Authentication Methods

Examples:
    Global Administrator

Highest Entra ID role.
Can:
    Manage users
    Manage groups
    Create admins
    Reset passwords
    Configure Conditional Access
    Manage tenant settings

User Administrator
Can:
    Create users
    Delete users
    Reset passwords
    Manage groups

Cannot:
    Manage Azure subscriptions

Security Administrator

Can:
    Manage security settings
    View security reports
    Manage security incidents

Conditional Access Administrator
Can:
    Create CA policies
    Modify CA policies

Cannot:
    Create Azure VMs

Example
    Elijah is a User Administrator
    Can:
    ✅ Create users
    ✅ Reset passwords

    Cannot:
    ❌ Create a VM
    ❌ Delete Storage Account

Reason: User Administrator is an Entra ID Role, not an Azure Role.

2. Azure Roles (Azure RBAC)
Azure Roles control access to Azure resources.
RBAC = Role-Based Access Control.
These roles are assigned at:
        Management Group
            ↓
        Subscription
            ↓
        Resource Group
            ↓
        Resource


Examples:
Owner
    Highest Azure role.
Can:
    Create resources
    Delete resources
    Assign RBAC permissions
    
Contributor
Can:
    Create resources
    Modify resources
    Delete resources
Cannot:
    Assign RBAC roles

Reader
Can:
    View resources
Cannot:
    Modify resources

Virtual Machine Contributor
Can:
Manage VMs only

Example
Elijah = Contributor
Can:
✅ Create VM
✅ Delete Storage Account
Cannot:
❌ Assign Owner role

Reason: Contributor is an Azure Role.

3. Azure AD Roles vs Entra ID Roles
These are the same thing.
Microsoft renamed:
        Azure Active Directory (Azure AD)
                ↓
        Microsoft Entra ID

Therefore:
        Azure AD Roles
                =
        Entra ID Roles


Examples:
Old Name	                    New Name
Azure AD Global Administrator	Entra ID Global Administrator
Azure AD User Administrator	    Entra ID User Administrator
Azure AD Security Administrator	Entra ID Security Administrator


Side-by-Side Example
Suppose you have:
    Tenant:
    Contoso

Entra ID Role
    Elijah
    Role: Global Administrator

Can:
    ✅ Create users
    ✅ Reset passwords
    ✅ Configure MFA
    ✅ Create Conditional Access policies

Cannot automatically:
    ❌ Create Azure VM
    ❌ Delete Storage Account

Azure Role
    Elijah
    Role: Contributor
    Subscription: Production


Can:
    ✅ Create VM
    ✅ Create Storage Account
    ✅ Create SQL Database


Cannot automatically:
    ❌ Manage Entra users
    ❌ Reset passwords

Interview Answer
        Entra ID Roles (formerly Azure AD Roles) provide permissions to manage identities and directory resources such as users, groups, MFA, applications, and Conditional Access. 
        Azure Roles (RBAC) provide permissions to manage Azure resources such as virtual machines, storage accounts, networking, and subscriptions. 
        Azure AD Roles and Entra ID Roles are the same concept; 
        Entra ID is simply the new name for Azure AD. 
        The two role systems are independent, and having permissions in one does not automatically grant permissions in the other.
